Phase 03 · Quantum-safe response

Protect the key layer,
not just the message.

The practical answer is not to invent “quantum encryption” from scratch. It is to adopt post-quantum cryptography, migrate carefully, and use specialist quantum hardware only where it makes sense.

01

Post-quantum cryptography

The scalable software-first option.

Use standardised algorithms such as ML-KEM to establish keys in a way designed to resist known quantum attacks. This can be adopted in applications, servers, and protocols without laying quantum fibre.

RECOMMENDED FIRST STEP

02

Hybrid migration

Protect now while upgrading safely.

Use current cryptography and post-quantum cryptography together during the transition. First inventory where RSA/ECC are used, then update the most sensitive, long-lived data.

PRACTICAL FOR MOST ORGANISATIONS

03

Quantum key distribution

A specialised hardware option.

QKD uses quantum states to detect eavesdropping during key exchange. It can be valuable for dedicated critical links, but requires specialised infrastructure and is not the default solution for every organisation.

What this is—and is not: ML-KEM is the NIST FIPS 203 post-quantum key-establishment standard. This demo really generates keys, establishes a shared secret, and encrypts the message locally. It does not implement identity authentication, server-side key storage, or a complete production messaging protocol.

AFFORDABLE ROADMAP

How an organisation can start

  1. 01

    Find vulnerable systems. Create an inventory of where RSA and ECC are used.

  2. 02

    Prioritise long-life data. Protect records that must remain confidential for many years.

  3. 03

    Test PQC in hybrid mode. Start with software upgrades before expensive hardware.

  4. 04

    Use QKD selectively. Reserve it for critical point-to-point links where the cost is justified.
