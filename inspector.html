ATTACKER VIEW

What an interceptor can and cannot obtain

The public channel is not secret. Security comes from the fact that public values do not reveal the session key.

CAN OBSERVE

  • ML-KEM public-key fingerprint
  • ML-KEM ciphertext fingerprint
  • AES-GCM IV and ciphertext

CANNOT OBSERVE

  • Alice’s ML-KEM secret key
  • Alice / Bob shared secret
  • AES-256 session key

SECURITY COMPARISON

Where the post-quantum advantage actually is

There is no honest “10× safer” score. Properly implemented RSA/ECC is secure against current classical attacks; post-quantum cryptography changes the risk specifically when a cryptographically relevant quantum computer exists.

LayerTypical current designQuantumShield design
Key establishmentRSA or ECCML-KEM-768
Security basisInteger factoring / discrete logarithmsModule Learning With Errors (lattice problem)
Against current computersStrong when correctly deployedStrong when correctly deployed
Against a future large quantum computerVulnerable to Shor’s algorithmDesigned to resist known quantum attacks
Data encryptionAES-256-GCM can still be usedAES-256-GCM can still be used
Trade-offSmaller public-key materialLarger keys/ciphertexts; no quantum hardware required

The key insight: ML-KEM does not make AES “more encrypted.” It replaces the quantum-vulnerable public-key layer used to establish the AES key. ML-KEM is standardised by NIST as FIPS 203. Read FIPS 203 →
